# 共通(全ファイル)

## 疑義の上げ方

コード構成の規則(層・依存・副作用・置き場)と検査の定義(`tests/Architecture/Policy/`・`phpstan.neon`・台帳)を黙って変えない。規則に合わない実装が要ると分かったら作業を止め、「箇所・問題・提案・影響範囲」を書いて判断を仰ぐ。規則に触れない内部の実装は裁量で直してよい。

## 上限を超えたとき

大きさの上限(`phpstan.neon` のクラス・メソッド・認知的複雑度、画面側のファイル 300 行・関数 50 行、物理行 120 字)を超える実装は、分け方を見直して上限の中に収める。新しいファイル・関数はベースラインに足さない。ベースラインに載ったファイルを変えたら、減った行を同じ変更で下げ、移動・改名ではキーを付け替える(値は同じか下げる。正本 = docs リポジトリの `設計/コード構成/検査.md` の 6 節「ベースライン」)。不自然な分割で押し込まない。上限の中で満たせないときは、失敗した検査・原因・上限の中でできる対応を示して未完了と報告する。

## 検査が見ないもの

機械検査が止めるのは、層・モジュール・副作用・置き場・大きさ・行の長さ・参照の実在・正規表現の `$`・経緯の語と、検査を外すこと(台帳⑧)だけ。クラスの分け方・命名・責務の置き方・役割の判定の置き場は検査しない。意味を読まないと判定できない規約は機械で止めず、コードレビューで見る。コードのレビューの扱いは docs リポジトリの根の `../docs/README.md` の「レビューの規約」。

## コメント

なぜそうしたか(1〜2 行)と docs の節の参照だけを書き、docs の手順・判定の順・表を写さない(対象外 = 静的解析の注釈と、docs が書き方を決めた PHPDoc)。`work/` にだけある番号と段の名前は書かない(段の数は「N 段目」と書く = docs リポジトリの `設計/コード構成/検査.md` の 6 節)。正本 = docs リポジトリの `設計/コード構成/否決案と指針.md` の 8 節。

## 名前

概念の名前は docs リポジトリの `設計/コード構成/用語集.md` の正の名前で書く。揺れた名前を直すのは、宣言と参照のすべてが今の変更で触るファイルの中にある名前だけ(クラス・公開の口・docs が名指す名前は、そのクラスの責務を変える変更のときに直し、名前だけを直す変更はしない。正本 = 8 節)。

## 作業木で走らせるとき

- PHPUnit を使うコマンド(`vendor/bin/phpunit`・`php artisan test`)は、作業木の中から(サブシェルで `cd` して)走らせる。どちらも cwd の `vendor/` の PHPUnit を起こし、その autoload が cwd の側のクラスを読むので(`vendor/bin/phpunit` は設定も cwd の `phpunit.xml` を読む)、作業木を絶対パスで指しても、cwd が別の作業木なら、そちらの古いクラスで走る。`composer --working-dir=` と `npm --prefix` は cwd に依らない
- 作業木では、`DOCS_ROOT`(環境変数か `.env`)に対の docs の作業木(`../<docs の作業木>`)を渡す(docs リポジトリの `設計/コード構成/検査.md` の 6 節)。無いと docs の参照の照合が失敗する(本体の docs を黙って読まない)。本体の docs を渡すと、照合は渡した docs だけを読むので、対の docs で直した参照とは照合しない
- 新しい作業木では、composer install と npm ci の後に `npm run build` を先に 1 回走らせる。wayfinder の生成物(`resources/js/actions`・`routes`・`wayfinder`。追跡しない)は build が作るので、build の前は `npm run check`・`types:check` が落ちる
- 画面側の整形の誤りは `npm run check` の出力を見て直し、`npx prettier` を使わない(書式が Oxfmt と違い、ファイル全体が書き換わる)

## デモユーザー切替の英字の名前

- デモユーザー切替の持ち物と取り付けの行(docs リポジトリの `設計/デモユーザー切替/デモの取り付け.md` の 6.1)の外では、そのモジュールの英字の名前を、大文字小文字を問わず語として書かない(クラス名・設定のキー・環境変数・ルートとファイルのパスの一部を含む)。README・コメント・docblock・この規則のファイルも照合の対象(同じ文書の 6.4)。日本語の「デモ」は当たらない
- 指したいときは「デモユーザー切替の初期データの seeder(同じ文書の 6.3)」のように日本語と docs の節で言い換える。取り付けの行を増やして通さない(規則の上書きになる)。コードレビューの指摘が英字の名前で書く直し方を出しても従わない
- 直した後は `php artisan test tests/Architecture --filter Footprint` で確かめる(DB を使わない)
